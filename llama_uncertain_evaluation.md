# Can Llama Adjudicate the UNCERTAIN Band? — Evaluation

_For blocks the GRU routes as **Uncertain**, Llama 3.2:1b returns a constrained Normal/Suspicious verdict grounded only in the Drain templates. Generated by `evaluate_uncertain.py`; classifier in `llm/uncertain_classifier.py`._

## The design decision (does Llama make the call?)

**Yes — but advisory and constrained, so hallucination protection is *strengthened*, never weakened.** Llama proposes `CLASSIFICATION / CONFIDENCE / EVIDENCE / EXPLANATION`; Python validates the label ∈ {NORMAL, SUSPICIOUS} and scrubs the prose through the **production scrubbers** (verdict → speculation → banned-cause) **plus a supplementary security-term scrubber** (malware / insider / threat / cyberattack / … — the professor's terms the production list lacked). The production deterministic detector (`main.py --detect`) is untouched; this measures whether the Llama step is safe and useful enough to add.

## Setup

- Uncertain test blocks available: **1,297**; randomly evaluated: **80** (seed 42).
- Of those 80, **27** are truly anomalous and **53** truly normal (the uncertain band is genuinely mixed — 33.8% anomalous).
- Llama temperature = 0 (reproducible). Model: `llama3.2:1b`.

- **Normal: 78 (97.5%)**  ·  **Suspicious: 2 (2.5%)**.
- Insufficient-evidence fallbacks (Llama declined to guess and returned the exact 'insufficient evidence' sentence): **78 (97.5%)**.

## Agreement between GRU routing and Llama's decision

- The GRU's provisional call for an uncertain block is **Normal** (it stayed below the Suspicious threshold). Llama **agreed (kept Normal)** on 78 (97.5%) and **overrode to Suspicious** on 2 (2.5%).
- Of the 2 overrides, **0 were correct** (the block really was anomalous) and 2 were false alarms.

## Does Llama actually add value here? (honest baselines)

| Decision rule | Accuracy on the uncertain band |
|---|---|
| Always say "Normal" (trivial) | 66.2% |
| Deterministic keyword rule (actual template has a failure token) | 75.0% |
| **Llama 3.2:1b (constrained)** | **63.7%** |

Confusion (Llama vs truth): TP=0 · FP=2 · TN=51 · FN=27.

## Observed 1B-model failure modes

- **Near-random discrimination:** recall 0.0% (0/27 true anomalies caught) at a 3.8% false-positive rate — Llama flags 2.5% of blocks Suspicious vs the true 33.8%, but on the *wrong* blocks. Its verdicts are essentially uncorrelated with truth on this deliberately-hard band.
- **Degenerate confidence:** 100.0% of responses report confidence of exactly 0% or 100% — the 1B model does not produce a calibrated confidence; the self-reported number is not usable as a routing signal.
- **Prompt-parroting:** many EVIDENCE lines echo the instruction text (e.g. "the actual event's template records a failure, exception, error...") instead of quoting the real template — which the scrubbers then correctly strip (hence the high scrub rate). The model often cannot extract genuine evidence from the templates.

## Recommendations for improving the prompt

- **Line-fields beat JSON** for a 1B model — strict `LABEL:` lines parsed by regex were reliable (100.0% parsed). JSON from 1B models frequently breaks.
- **Conservative default**: when evidence is insufficient, instruct (and default to) NORMAL, so the LLM cannot inflate the suspicious rate on ambiguous logs.
- **Failure-token guidance**: telling the model that exception/error/failed/interrupted in the *actual* template is the signal for SUSPICIOUS keeps its reasoning grounded.
- **Keep the scrubbers as a hard backstop** regardless of prompt quality — they are what make hallucination *structurally* impossible, not the prompt.

## Honest verdict — are prompt fixes enough, or do model limits remain?

- **Hallucination is controlled.** No unsupported banned cause appeared in the raw output, and the scrubbers guarantee zero survive regardless. Prompt constraints + scrubbers are sufficient on this axis — no model change needed for safety.
- **Honest negative:** Llama (63.7%) does **not** beat the trivial always-Normal baseline (66.2%). On this band the 1B model does not reliably adjudicate; keep Llama as an *explainer* and let the GRU surprise score (or the keyword rule) make the decision. This is a model-capacity limit, not a prompt bug — prompt tweaks will not close a gap this size.
- **Recommendation:** keep the production deterministic detector as the decision-maker; use Llama for grounded *explanation*. If a Llama verdict is wanted on Uncertain blocks, deploy it only in the **constrained advisory** form evaluated here (Python validates + scrubs), never as an unchecked classifier.
