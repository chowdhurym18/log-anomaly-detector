## 2. Strengths & weaknesses

| Score | Strength | Weakness |
|---|---|---|
| combined_z(nll_max)+z(miss_count) | Fuses two orthogonal signals (peak surprise + violation count), z-fit on validation. | Adds a moving part; only helps when BOTH component signals are informative. |
| nll_rolling_max(w=5) | Captures a sustained BURST of surprise (max over a moving average), not one spike — robust to isolated noise. | Window size is a hyperparameter; weak on very short blocks. |
| topk_miss_count | Raw count of out-of-top-k violations in the block. | Confounded with block length; coarse, low PR-AUC. |
| topk_miss_frac | Classic DeepLog top-k violation rate; parameter-light and interpretable. | Binary per window → coarse; near-random unless the model is trained normal-only. |
| nll_-logp_mean | Proper unbounded surprise (−log p) averaged over the block — well-calibrated, robust to block length. | A single catastrophic transition can be diluted by many ordinary ones in a long block. |
| surprisal_1mp_mean | Smooth average surprise, bounded [0,1]. | Saturates like 1−p and dilutes single spikes. |
| msp_self_uncertainty (1-MSP, max) | The model's confidence in its OWN top prediction — the best 'is this prediction correct' signal. | Measures self-confidence, NOT whether the ACTUAL event was surprising → the WORST block detector. |
| surprisal_1mp_max | DeepLog max rule on a bounded [0,1] scale — directly interpretable as a probability. | `1 − p` saturates at 1, so it cannot tell a p≈1e-3 transition from a p≈1e-9 one. |
| nll_-logp_max | Flags the single most surprising transition (DeepLog's rule) on the unbounded NLL scale. | One noisy spike (a rare-but-benign event) can trigger a false positive. |
| nll_perevent_z_max | Per-event-calibrated peak surprise (DeepLog max rule after per-template z-scoring). | A single noisy spike on a poorly-estimated template can trigger a false positive. |
| nll_perevent_z_mean | Per-event-type calibration: each window's NLL is z-scored against its TARGET event's reference distribution — 'surprising for THIS template', key on large vocabularies. | Needs enough reference windows per event; rare templates fall back to global stats. |

## 3. Recommendation

- **Primary detector signal: `combined_z(nll_max)+z(miss_count)`** — the best separator by validation PR-AUC (val PR-AUC 0.9915; test PR-AUC 0.9946, F1 0.9679). This is what the production detection pipeline should use to rank blocks.
- **Gate check vs the current production default (`nll_-logp_mean`):** val PR-AUC gap = +0.0387 (0.9527 → 0.9915), meets the ≥0.005 bar. Uncertain-band check (val, min workable size 47): `combined_z(nll_max)+z(miss_count)` leaves **0** blocks Uncertain vs `nll_-logp_mean`'s 79. **This is below the workable minimum — adopting `combined_z(nll_max)+z(miss_count)` would starve the Uncertain→Llama adjudication stage of cases, defeating the routing architecture even though it detects better in isolation.**
- **Decision: Do NOT adopt `combined_z(nll_max)+z(miss_count)` as the production detection score for this dataset.**
- **Key finding — do NOT use `nll_perevent_z_mean` for detection here.** It is the worst separator on this dataset (val PR-AUC 0.2129, AUROC 0.653). Needs enough reference windows per event; rare templates fall back to global stats.
- **MSP self-uncertainty is also unsuitable as a detector** (val PR-AUC 0.8937 here) even though it is not the worst on this dataset: it measures the model's confidence in its OWN top prediction (great for routing 'is this prediction correct?'), NOT whether the ACTUAL event was surprising — what suspicious-activity detection needs. The old hybrid pipeline routes correctness; the detector must route surprise.
- `-log p` (NLL) beats `1 − p`: NLL's unbounded tail distinguishes a p≈1e-6 transition from a merely-unlikely one, while `1 − p` saturates at 1.
